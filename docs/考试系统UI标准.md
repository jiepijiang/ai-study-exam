# AI Agent 学习考试系统 UI 标准

> 版本：1.0
> 更新日期：2026-09-27
> 适用范围：`09-考试检测系统/index.html` 及 GitHub Pages 发布副本

## 1. 产品定位

这是一个面向嵌入式团队应用工程师的个人学习证据台。它的核心工作不是展示课程，而是帮助用户每天完成任务、提交可复核证据、参加周测、处理复习队列，并查看掌握度与门禁状态。

界面应当像一张安静、可靠的工程记录台：信息密度可控、状态可判断、操作可恢复。禁止将页面做成营销首页、装饰性 Dashboard 或只适合桌面端的表格。

## 2. 设计原则

1. **先行动后解释**：首屏先给出当前进度、当前周次和下一步操作。
2. **状态可读**：完成、待补证据、到期复习、门禁未通过必须有颜色、文字和结构三重表达。
3. **证据优先**：任务文本、产出、证据表单按“做什么 -> 产出什么 -> 如何复核”排序。
4. **渐进披露**：默认只展示完成任务所需字段；说明和历史放在次级区域。
5. **移动端同等可用**：H5 不缩小桌面布局，而是改变信息排列和操作方式。
6. **不破坏数据**：UI 只能改变展示与交互，不改变题库判分、门禁、复习和 `localStorage` 数据契约。

## 3. 信息架构

### 3.1 一级导航

| 视图 | 业务任务 | 桌面端位置 | H5 位置 |
| --- | --- | --- | --- |
| 每日打卡 | 完成任务并登记证据 | 左侧主导航第一项 | 底部导航第一项 |
| 周测 | 开始、作答、提交和重考 | 左侧主导航第二项 | 底部导航第二项 |
| 复习队列 | 处理到期复习题 | 左侧主导航第三项 | 底部导航第三项 |
| 掌握度 | 查看 skill 和 M1-M4 门禁 | 左侧主导航第四项 | 底部导航第四项 |
| 报告 | 复制或下载可复核记录 | 左侧主导航第五项 | 底部导航第五项 |

导航文案必须和页面标题一致。普通操作图标使用 Lucide 风格的本地 SVG 路径或内联图标，不使用 emoji，不使用 Vue 标志。品牌 Logo 使用独立的原创 SVG 资产。

### 3.2 桌面端布局（>= 960px）

```text
┌──────────────┬─────────────────────────────────────────────┐
│ 品牌 / 版本   │ 页面标题                         保存状态    │
│               ├─────────────────────────────────────────────┤
│ 每日打卡      │ 页面工具条 / 周次选择 / 主操作               │
│ 周测          │                                             │
│ 复习队列      │ 主内容区：任务、题目、状态、报告              │
│ 掌握度        │                                             │
│ 报告          │                                             │
└──────────────┴─────────────────────────────────────────────┘
```

- 侧栏宽度 `232px`，固定在视口左侧；内容区最大宽度 `1180px`。
- 页面主内容左右内边距 `32px`，顶部 `28px`。
- 桌面端导航仅承担视图切换，不与业务卡片混排。
- 页面标题、主操作和保存状态在同一工具条中保持可见。

### 3.3 H5 布局（< 960px）

- 顶部仅保留 Logo、页面标题和保存状态；高度不超过 `64px`。
- 主内容横向内边距 `16px`，卡片之间 `12px`。
- 一级导航改为底部固定导航，高度 `72px`，包含安全区 `env(safe-area-inset-bottom)`。
- 导航项只显示图标和短标签，触控目标最小 `44px × 44px`。
- 桌面五列表格转换为“横向滚动表格”或“字段分组列表”，不得强制页面整体横向滚动。
- 任务证据表单从多列网格切换为单列；状态和证据等级可在同一行，其余字段逐行展示。
- 题目选项、代码输入、Rubric 复选框全部保持可触控间距。

## 4. 视觉 Token

### 4.1 颜色

采用浅中性背景和青绿操作色，红色只用于错误或安全红线，琥珀只用于待处理状态。

```css
--color-canvas: #f4f6f5;       /* 页面背景 */
--color-surface: #ffffff;      /* 一级表面 */
--color-surface-muted: #edf2f0;/* 次级表面 */
--color-ink: #17221f;          /* 主文字 */
--color-ink-muted: #60706b;    /* 次级文字 */
--color-line: #d8e2de;         /* 分割线 */
--color-brand: #0f766e;        /* 主操作 */
--color-brand-strong: #115e59; /* hover / active */
--color-brand-soft: #d9f0eb;   /* 品牌浅底 */
--color-info: #2563eb;         /* 信息 */
--color-success: #15803d;      /* 有效完成 */
--color-warning: #b45309;      /* 待处理 */
--color-danger: #b42318;       /* 错误 / 红线 */
--color-danger-soft: #fee4e2;
```

颜色不能作为唯一状态信号。状态必须同时包含文字或图标，且通过对比度检查：正文至少 `4.5:1`，大字至少 `3:1`。

### 4.2 字体

- 中文正文：`"Microsoft YaHei", "PingFang SC", system-ui, sans-serif`。
- 英文和数字：`ui-monospace, "Cascadia Code", Consolas, monospace` 仅用于命令、哈希、版本和证据 ID。
- 页面标题 `24px / 1.3 / 700`；区块标题 `16px / 1.4 / 700`；正文 `14px / 1.6 / 400`；辅助文本 `12px / 1.5 / 400`。
- 不使用负字距，不随视口缩放字号。移动端页面标题最低 `20px`。

### 4.3 间距和尺寸

以 `4px` 为基础单位，常用值为 `4 / 8 / 12 / 16 / 20 / 24 / 32`。

- 卡片内边距：桌面 `20px`，H5 `16px`。
- 卡片间距：`16px`，紧密列表项间距 `8px`。
- 字段标签与控件：`6px`；控件与控件：`8px`。
- 标准控件高度 `40px`；紧凑控件最低 `36px`；触控目标最低 `44px`。
- 边框圆角统一 `6px`；状态标签可用 `999px`，不得用大圆角卡片。
- 不使用卡片套卡片。主页面区域用分隔线和留白组织，卡片只用于重复记录、题目、门禁和报告等确需成组的对象。

## 5. 组件规范

### 5.1 品牌和图标

- 品牌标识为“路径节点 + 校验闭环”的原创几何 Logo，文件位于 `09-考试检测系统/assets/brand-mark.svg`。
- favicon 使用同一几何母题的简化版，位于 `assets/favicon.svg`。
- 操作图标统一 `18px`，线宽 `1.8`，使用 `currentColor`；图标旁应有可读的 `aria-label` 或可见短标签。
- 不使用 Vue 图标、Vue 绿色三角、烧杯 emoji 或其他与产品无关的图形。

### 5.2 按钮

- 主操作：实心品牌色，文案使用动作动词，例如“开始周测”“提交并记录”。
- 次操作：白底描边，例如“重新计算”“下载 Markdown”。
- 危险操作：仅用于清空数据和安全红线，必须有确认步骤。
- 图标按钮只有在图标语义明确时使用，并提供 tooltip 和 `aria-label`。
- disabled 状态降低对比度但保留文字，不得只靠透明度表达不可用原因。

### 5.3 状态标签和提示

- `有效完成`：绿色 + “完成”文案。
- `待补证据`：琥珀色 + “待补证据”。
- `未通过 / 阻塞`：红色 + 具体原因。
- `信息`：蓝色 + 事实描述。
- 提示必须紧邻产生问题的控件，说明下一步，不写空泛的“操作失败”。

### 5.4 每日任务

任务块的固定顺序：

1. Day、任务类型、预计分钟数、当前状态。
2. 任务说明。
3. 产出说明。
4. 证据等级和证据字段。
5. 即时校验提示。

桌面端证据字段采用两列以上网格，但摘要始终整行；H5 切换单列。字段必须有 label 或可被辅助技术识别的 placeholder，不以 placeholder 代替唯一标签。

### 5.5 题目和答题

- 每道题显示题号、技能标签、题型和分值，再显示题干。
- 选项使用整行可点击区域；单选使用 radio，多选使用 checkbox。
- 代码题和场景题分离“开放作答”和“可复核证据”，不把两者合并为一个长文本框。
- 提交按钮固定出现在试卷末尾；题目较长时在顶部提供进度摘要。
- 历史记录默认展示得分、通过状态、题型和证据摘要；窄屏允许表格横向滚动。

### 5.6 掌握度和报告

- 掌握度表格优先显示 `skill_id / M_final / 题型覆盖 / 门禁 / 状态`。
- 报告使用等宽字体、浅色代码表面和独立复制/下载操作。
- 空状态必须解释数据产生方式，例如“提交周测后自动建立复习队列”。

## 6. 交互状态

所有主要控件至少覆盖：默认、hover、focus-visible、active、disabled、错误、空状态。

- `:focus-visible` 使用 `2px` 品牌色外描边，不能移除浏览器焦点。
- 切换视图后焦点回到新视图标题或第一个主要控件。
- 变更立即保存时，顶部保存状态更新为时间；保存异常时显示错误文本。
- 题目提交前不清空作答内容；提交后保留本次结果并追加历史。
- 破坏性操作使用确认对话框，明确“清空本地 v3 数据”不可恢复。
- `prefers-reduced-motion: reduce` 时关闭动画和过渡。

## 7. 响应式断点

| 断点 | 规则 |
| --- | --- |
| `>= 1200px` | 232px 侧栏 + 1180px 内容，任务证据五列网格 |
| `960-1199px` | 侧栏缩窄，任务证据三列网格 |
| `600-959px` | 顶部导航或可收起侧栏，任务证据两列网格 |
| `< 600px` | 底部导航，单列任务表单，卡片内边距 16px |

验收宽度至少包含 `1440x900`、`1024x768`、`768x1024`、`390x844`。

## 8. 无障碍和工程约束

- HTML 使用 `header / nav / main / section / form / fieldset / legend` 等语义元素。
- 页面保持 `lang="zh-CN"`，每个输入控件可通过 label 关联。
- 键盘可完成导航、选择周次、作答、提交和导出；Tab 顺序与视觉顺序一致。
- 不依赖 hover 才能获得关键信息；触屏无 hover 时仍可用。
- 长文本使用 `overflow-wrap:anywhere`，表格只在自身容器内滚动。
- 所有由 JavaScript 生成的 HTML 必须继续使用现有 `esc()`，不得引入未转义题库文本。
- 保持以下业务 ID 不变：
  `checkWeekSel`、`weekSel`、`startBtn`、`retakeBtn`、`examBody`、
  `examHistory`、`reviewBody`、`masteryBody`、`reportBody`、
  `refreshReviewBtn`、`refreshMasteryBtn`、`copyMd`、`downloadMd`、
  `downloadJson`、`resetBtn`。
- 不修改 `ai-agent-learning-evidence-v3` 存储键和已有数据结构；新增的 `activeExam` 仅用于恢复进行中的未提交试卷，可为空，不覆盖考试历史。

## 9. UI 验收清单

### 视觉

- [ ] 无 Vue 图标、emoji 导航或烧杯 Logo。
- [ ] PC 和 H5 的主操作在首屏可见，标题、状态、控件不重叠。
- [ ] 所有卡片圆角不超过 `8px`，无卡片套卡片。
- [ ] 表格、题干和证据摘要不溢出页面；移动端不出现整体横向滚动。
- [ ] 状态不只依赖颜色，文字和结构清晰。

### 功能

- [ ] 五个导航视图均可切换，当前项有清晰 active 状态。
- [ ] `?date=&week=&tab=` 深链接仍能预选周次和视图。
- [ ] 打卡字段、周测作答、复习、掌握度门禁和报告导出逻辑不回归。
- [ ] 原有 `localStorage` 数据可以被页面继续读取和更新。
- [ ] 清空数据仍有确认提示，且只删除本应用 v3 数据。

### 设备和无障碍

- [ ] 在 `1440x900`、`1024x768`、`768x1024`、`390x844` 检查无重叠。
- [ ] 键盘可访问所有导航、输入、复选框和按钮。
- [ ] `focus-visible` 清晰，缩放到 200% 时主要内容仍可读。
- [ ] 减少动态效果设置生效。
